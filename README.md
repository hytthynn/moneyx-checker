# Money-X Checker

Приватный Telegram-бот, который получает курсы пополнения Money-X, отправляет один почасовой отчёт в выбранную группу и управляется только пользователем с `ADMIN_TELEGRAM_ID`.

Бот **не создаёт заявки на пополнение и не выполняет финансовые операции**. Для пар без курса в `crypto/list` он всегда запрашивает курс через `crypto/wallet`. Адреса кошельков и тела API-ответов не сохраняются и не логируются.

## Возможности

- webhook на Vercel и long polling для локальной разработки;
- Supabase PostgreSQL для настроек, зашифрованных токенов, истории и идемпотентности;
- курсы для каждой пары `currency + network`, исходный порядок и точная дедупликация;
- частичные отчёты, retry временных ошибок и общий deadline;
- фиксированное расписание `HH:02` по `Europe/Moscow`; каждый вызов cron запускает новую рассылку;
- безопасная смена домена с DNS/redirect SSRF-проверками и атомарным сохранением;
- группа или супергруппа из `TELEGRAM_GROUP_ID`; пользовательские сообщения в ней удаляются, команды доступны только в личном чате;
- настраиваемый в панели порог роста курса для отдельных уведомлений; в уведомлении показывается только процент роста;
- одноразовые оповещения об истёкшей сессии и недоступной группе.

## Быстрый локальный запуск

Требуется Python 3.12–3.14 и созданный проект Supabase. Локальный запуск и Vercel используют одну и ту же внешнюю базу. Зависимости содержат готовые Windows wheels для Python 3.14, поэтому Visual C++ Build Tools не требуется.

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
python -m scripts.generate_key
python main.py
```

До `python main.py` заполните `.env` и один раз выполните SQL из `migrations/001_initial.sql` в **Supabase Dashboard → SQL Editor**. Запишите сгенерированный ключ в `APP_ENCRYPTION_KEY`. Не меняйте этот ключ без предварительной ротации данных: старые токены перестанут расшифровываться.

## Переменные окружения

В `DATABASE_URL` вставьте строку **Transaction pooler** из Supabase с портом `6543`. Обычный `postgresql://` автоматически преобразуется в драйвер `psycopg`, а SSL включается автоматически.

Обязательные для запуска бота: `TELEGRAM_BOT_TOKEN`, `ADMIN_TELEGRAM_ID`, `TELEGRAM_GROUP_ID`, `TELEGRAM_WEBHOOK_SECRET`, `CRON_SECRET`, `APP_ENCRYPTION_KEY`, `DATABASE_URL`. Для Vercel также задайте `APP_BASE_URL`. `TELEGRAM_GROUP_ID` — отрицательный ID группы или супергруппы.

Авторизация Money-X хранится в базе в зашифрованном виде. Настройте её через `/start` → «Изменить авторизацию» в личном чате либо выполните на доверенной машине `python -m scripts.set_auth`; ввод в консоли скрыт.

Коэффициент курса зафиксирован на `1`, параллелизм — на трёх запросах, а `crypto/wallet` всегда разрешён. Эти параметры намеренно не вынесены в `.env`.

## Обязательная верификация API (этап 0)

Сначала перевыпустите токен Money-X. Затем выполните:

```bash
python -m scripts.verify_moneyx
```

Скрипт проверит `/me` и `crypto/list`, не выводя токены или адреса. Если список уже содержит rate, `crypto/wallet` не нужен. Если rate отсутствует, сделайте **ровно один** контролируемый запрос и одновременно сравните число со страницей:

```bash
python -m scripts.verify_moneyx --wallet-sample --expected-visible-rate 90.167
```

Замените `90.167` на курс, который виден на сайте непосредственно во время запуска проверки.

Код вызывает исключительно `/v3/api/me`, `/v3/api/deposit/crypto/list` и `/v3/api/deposit/crypto/wallet`.

## Telegram

Укажите отрицательный ID целевой группы в `TELEGRAM_GROUP_ID` и добавьте туда бота администратором с правами отправлять и удалять сообщения. После преобразования группы в супергруппу Telegram выдаёт ей новый ID: обновите `TELEGRAM_GROUP_ID` в окружении. При запуске бот также распознаёт миграцию старого ID. Группа предназначена только для отчётов: сообщения пользователей, включая команды, бот автоматически удаляет. Сообщения других ботов не затрагиваются.

Единственная команда — `/start`. Она открывает панель администратора с inline-кнопками «Статус», «Проверить курс», «Изменить домен», «Изменить авторизацию» и «Порог роста». Все экраны и результаты ввода редактируют это же сообщение. «Проверить курс» обновляет отчёт только в группе; новое сообщение в личный чат не отправляется. Ввод настроек можно отменить, а введённое сообщение удаляется после получения. Порог можно задать, например, как `0.5%` или `0,5`; значение `0%` сохраняет уведомления о любом видимом росте. В сообщении «Курс вырос» выводятся только монеты, достигшие порога, и их рост в процентах.

Авторизацию можно обновить только в личном чате. Значение токена бот не повторяет. Telegram всё равно является сторонним транспортом, поэтому `scripts.set_auth` предпочтительнее.

## Vercel

Полная инструкция для Supabase, Vercel и внешнего cron находится в [VERCEL.md](VERCEL.md). Кратко: используйте Supabase Transaction pooler на порту `6543`, вручную выполните `migrations/001_initial.sql` в Supabase SQL Editor (для существующей базы — также `migrations/002_increase_threshold.sql`), добавьте production-переменные в Vercel, зарегистрируйте Telegram webhook и настройте внешний сервис на ежечасный `GET /api/hourly/02` с заголовком `Authorization: Bearer <CRON_SECRET>`.

Встроенный Vercel Cron не используется. Каждый вызов внешнего cron создаёт новую рассылку; короткая lease-блокировка в Supabase не позволяет двум проверкам выполняться одновременно. Приложение никогда не создаёт и не изменяет схему автоматически.

Vercel автоматически распознаёт ASGI-приложение `app` в `api/index.py`; Python закреплён на версии 3.14 через `.python-version`.

## Тесты и эксплуатация

```bash
pytest -q
ruff check .
```

При `401` токен помечается невалидным и администратор уведомляется один раз. При `403` бот не пытается обходить защиту. Если Telegram сообщает `bot was kicked` или `chat not found`, администратору отправляется одно уведомление; расписание остаётся активным.

Логи идут в stdout с уровнем `INFO`. Фильтр удаляет Bearer/cookie, Telegram-токены и поля адресов кошелька.

Перед приёмкой сравните все строки до третьего знака, проверьте отсутствие депозитов, два параллельных cron-вызова, смену/откат домена и отсутствие секретов в Git, логах и Telegram.
